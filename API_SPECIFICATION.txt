1. AUTHENTICATION & AUTHORIZATION
================================================================================

Authentication Method: JWT (JSON Web Tokens)
Header Format: Authorization: Bearer <access_token>

User Roles:
  - CUSTOMER: Regular users who create orders
  - COURIER:  Delivery personnel  
  - ADMIN:    System administrators

Token Expiration:
  - Access Token:  1 hour
  - Refresh Token: 7-30 days (not yet implemented)

[IMPLEMENTED] POST /auth/register
Description: Register a new user account (customer or courier)
Authentication: None
Request Body:
  {
    "email": "user@example.com",           // Required, valid email
    "password": "SecurePass123",           // Required, min 6 characters
    "first_name": "John",                  // Required
    "last_name": "Doe",                    // Required
    "phone_number": "+251911234567",       // Required
    "user_role": "CUSTOMER",               // Optional: CUSTOMER (default) or COURIER
    "date_of_birth": "1990-01-15"          // Optional: ISO date format
  }
Response 201:
  {
    "message": "User registered successfully",
    "user": {
      "user_id": "uuid",
      "email": "user@example.com",
      "first_name": "John",
      "last_name": "Doe",
      "phone_number": "+251911234567",
      "user_role": "CUSTOMER",
      "is_active": true,
      "is_verified": false,
      "created_at": "2025-12-19T09:00:00.000Z"

  }
Errors:
  - 400: Validation errors or user already exists
  - 500: Internal server error
Events Published:
  - user.created

--------------------------------------------------------------------------------

  201 Created           - Successful POST (resource created)

  400 Bad Request       - Validation errors, invalid data
  401 Unauthorized      - Missing or invalid authentication
  403 Forbidden         - Insufficient permissions
  404 Not Found         - Resource not found

APPENDIX B: SECURITY CONSIDERATIONS
================================================================================

1. Authentication:
   - Implement refresh token rotation
   - Store token hashes, not plaintext
   - Short access token expiry (15-30 min)
   - Implement token blacklist for logout

2. Authorization:
   - Verify resource ownership (user can only access own orders)
   - Role-based access control for admin endpoints
   - Courier can only update assigned orders

3. Input Validation:
   - Validate all inputs on server side
   - Sanitize user inputs to prevent injection
   - Use Zod/express-validator for schema validation

4. Rate Limiting:
   - Auth endpoints: 5 requests/minute
   - General API: 100 requests/minute
   - Location updates: 60 requests/minute

5. Data Protection:
   - Hash passwords with bcrypt (salt rounds: 10+)
   - Encrypt sensitive PII fields
   - HTTPS only in production
   - Secure headers (Helmet.js)

6. API Security:
   - CORS configuration (whitelist origins)
   - Request size limits
   - SQL injection prevention (Prisma parameterized queries)
   - XSS prevention (sanitize outputs)
